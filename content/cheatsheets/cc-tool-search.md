### Проблема

Каждое определение инструмента едет в **каждый** запрос. Подключённый MCP-сервер при
предзагрузке добавляет схемы **всех** своих инструментов — несколько серверов способны
съесть заметную часть окна ещё до того, как агент что-то сделал.

### Режимы

| Значение | Поведение |
|---|---|
| По умолчанию | Схемы MCP отложены, грузятся по требованию через tool search |
| `ENABLE_TOOL_SEARCH=auto` | Предзагрузка, если схемы укладываются в 10% окна контекста |
| `ENABLE_TOOL_SEARCH=false` | Грузить всё сразу |

⚠️ На неподдерживаемых моделях и некоторых платформах происходит **откат к предзагрузке** —
экономия исчезает молча. Проверяй, а не предполагай.

### Что сколько стоит

| Источник | Когда грузится |
|---|---|
| Встроенные схемы инструментов | Каждый запрос |
| Схемы MCP | По умолчанию отложены; при откате — каждый запрос |
| Имена MCP-инструментов | Всегда (сам список короткий) |
| Описания скиллов | На старте, короткими summary |
| Тело скилла | Только при вызове |

### Как сокращать

- Сужать набор инструментов сабагенту полем `tools` в его конфигурации.
- Ревизовать подключённые MCP-серверы: сервер «на всякий случай» платит за себя постоянно.
- Делегировать объёмное чтение сабагенту — содержимое останется в его окне.
- Понижать `effort` там, где агент только читает файлы.
