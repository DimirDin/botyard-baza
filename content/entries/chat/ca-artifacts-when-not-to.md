### ❓ Что это

Документация даёт определение через отрицание: артефакт — **снимок работы, а не
приложение**. Это одна самодостаточная страница без бэкенда: она не сохранит ввод формы
и не обслужит несколько маршрутов, а единственный её путь к внешним данным при
просмотре — вызовы MCP-коннекторов.

Для внутреннего инструмента с бэкендом документация советует деплоить его у себя.

### 🎯 Зачем тебе

Артефакт уместен там, где терминальный текст — неподходящий носитель: вывод, на который
удобнее смотреть и с которым удобнее повзаимодействовать, чем читать построчно.

| Подходит | Не подходит |
|---|---|
| Провести ревьюера по PR с аннотированным дифом | Форма, собирающая ответы |
| Дашборд по данным, уже собранным в сессии | Логин и разграничение доступа внутри страницы |
| Несколько вариантов дизайна рядом | Многостраничный сайт |
| Таймлайн расследования, заполняемый по ходу | Сервис, к которому обращается твой код |
| Ссылка коллеге вместо вставки вывода в мессенджер | Хранилище состояния между визитами |

### 💻 Минимальный пример

Проверочный вопрос перед тем, как просить артефакт:

```
Нужно ли странице что-то помнить между открытиями?   → значит, не артефакт
Нужен ли ей собственный API?                          → не артефакт
Нужно ли пускать не всех?                             → не артефакт (только шеринг целиком)
Достаточно ли показать и дать повзаимодействовать?    → артефакт
```

### ⚠️ Грабли

- **Интерактивность создаёт иллюзию приложения.** Слайдеры и перетаскивание работают, но
  результат исчезает при закрытии, если не выгружен.
- **Генерация стилизованной страницы токеноёмче обычного ответа.** Для короткой сводки
  терминальный текст дешевле и быстрее.
- **Артефакт с коннекторами нельзя сделать публичным** ни на одном плане.
