### ❓ Что это

**Claude Projects (Проекты)** — это встроенная в веб-интерфейс Claude.ai функция, позволяющая пользователям Pro и Team тарифов создавать изолированные рабочие пространства с собственной базой знаний (загруженными файлами) и постоянными инструкциями (Custom Instructions) для модели.

### 🎯 Зачем тебе

* **Постоянный контекст без повторной загрузки**: Вы можете один раз загрузить в проект спецификацию продукта, гайдлайны по коду, API-справку и примеры хороших ответов. Все последующие чаты внутри этого проекта будут автоматически «помнить» эти файлы.
* **Кастомизация поведения**: С помощью инструкций проекта можно задать роль для Claude (например, «Ты опытный QA-инженер, пишущий тест-кейсы на Python») и правила форматирования ответов.
* **Совместная работа (для Team тарифов)**: Проекты можно расшаривать внутри команды, создавая единую базу знаний по проекту для всех разработчиков или контент-мейкеров.

### 💻 Как это настроить

Эффективная структура проекта Claude строится по следующим шагам:

1. **Custom Instructions (Инструкции проекта)**:
   Задайте четкую роль, правила оформления кода и ограничения. Пример:
   ```markdown
   Роль: Технический писатель и архитектор.
   Правила оформления кода:
   - Всегда используй type hints в Python.
   - Пиши комментарии только к сложной бизнес-логике.
   - Оформляй ответы в сжатом академическом стиле.
   ```

2. **Project Knowledge (База знаний проекта)**:
   Загрузите ключевые файлы в секцию *Project Knowledge*:
   - `architecture-overview.md` — общая структура системы.
   - `api-spec.json` — Swagger/OpenAPI спецификация ваших эндпоинтов.
   - `styleguide.md` — правила форматирования и naming conventions.

### ⚠️ Грабли

* **Лимиты на размер файлов**: Проект имеет ограничение на суммарный объем загруженного текста (около 200 000 токенов на проект). Если вы попытаетесь загрузить туда весь свой репозиторий вместе с `node_modules` или собранными бинарниками, вы быстро исчерпаете лимит. Загружайте только ключевую документацию и файлы схем.
* **Устаревание информации**: В отличие от Git, файлы в Claude Projects не обновляются автоматически. Если вы изменили API в коде, не забудьте вручную обновить спецификацию в базе знаний проекта, иначе Claude будет генерировать код по старым контрактам.
* **Смешивание контекста**: Не пытайтесь создать один «супер-проект» для всех задач компании. Разделяйте проекты по конкретным продуктовым фичам или репозиториям — это улучшит точность ответов и сэкономит лимиты сообщений.
