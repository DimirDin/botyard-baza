### ❓ Что это

Агент в CI отличается от агента на вашей машине одним: никто не смотрит на экран. Цикл, который вы бы прервали через минуту, здесь крутится до упора, и умножается на количество push'ей всей команды.

### 🎯 Зачем тебе

**Четыре уровня предохранителей, каждый нужен:**

1. **Лимит на запуск** — `--max-turns` и `--max-budget-usd`. Ограничивают один прогон.
2. **Лимит на срабатывания** — не запускать на каждый коммит. Только на PR, только при изменении определённых путей, только по метке.
3. **Выбор модели по задаче** — линтинг и проверка стиля не требуют самой дорогой модели; `--fallback-model` спасает от простоя при перегрузке.
4. **Мониторинг расхода** — считать не «в среднем за месяц», а по прогонам, чтобы аномалия была видна сразу.

### 💻 Минимальный пример

```yaml
on:
  pull_request:
    paths: ['backend/**', 'frontend/src/**']   # не на каждый коммит

jobs:
  review:
    if: "!contains(github.event.pull_request.labels.*.name, 'skip-ai')"
    steps:
      - run: |
          claude -p "Ревью diff на баги и утечки секретов" \
            --output-format json \
            --max-turns 12 \
            --max-budget-usd 1.5 \
            --bare \
            --tools "Read,Bash(git diff:*)"
        timeout-minutes: 10
```

`timeout-minutes` на уровне CI — последний рубеж: он сработает, даже если флаги агента не помогли.

### ⚠️ Грабли

* **Большой diff = большой счёт.** PR с автогенерированным кодом или обновлением lock-файла может стоить как весь остальной месяц. Фильтруйте пути.
* **Форки и внешние PR.** Запуск агента с секретами на PR из форка — это не про деньги, а про безопасность.
* **Ретраи CI умножают расход.** Три перезапуска упавшего job — тройная стоимость.
* **Кэширование промптов.** Одинаковая объёмная преамбула в каждом прогоне — кандидат на prompt caching, это заметно дешевле.
