### ❓ Что это

В интерактивной работе загрузка проектных инструкций — благо. В CI это ещё и поверхность
доверия: агент прочитает `CLAUDE.md` и `.claude/rules/` из того, что лежит в ветке —
включая ветку из внешнего пулл-реквеста.

Флаг `--setting-sources` управляет тем, какие слои настроек подхватываются. Исключишь
`project` — проектные правила пропускаются. Исключишь `local` — не подхватится
`CLAUDE.local.md`.

### 🎯 Зачем тебе

Три практических следствия для автоматических запусков:

- **Инструкции из ветки — это ввод, а не конфигурация.** Тот, кто прислал PR, может
  добавить строчку в `CLAUDE.md`. Полагаться на них как на защиту нельзя — защита
  живёт в managed-настройках и хуках.
- **Артефакты в CI выключены по умолчанию.** В контекстах Agent SDK, GitHub Action и
  MCP-сервера публикация артефактов не работает без явного включения.
- **Сессия на API-ключе публиковать не может** в принципе — это ограничение
  аутентификации, а не настройки.

### 💻 Минимальный пример

```bash
claude -p "проверь диф на регрессии" --output-format json --setting-sources user
```

Так агент возьмёт твои пользовательские настройки, но не станет читать инструкции из
проверяемой ветки. Для языков без SDK это же и есть штатный путь: документация прямо
предлагает запускать CLI подпроцессом с `-p` и `--output-format json`.

### ⚠️ Грабли

- **До версии 2.1.211 правила с отложенной загрузкой грузились даже при исключённом
  `project`** — path-scoped и вложенные `.claude/rules/`. На старых версиях изоляция
  была неполной.
- **Бюджет надо ставить явно.** Без `max_turns`/`max_budget_usd` цикл крутится, пока
  модель не решит, что закончила, — в CI это открытый счёт.
- **`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` меняет доступность фич**, а не только
  телеметрию: с ним артефакты тоже отключаются.
