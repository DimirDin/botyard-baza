### ❓ Что это

`CLAUDE.md` работает как инструкция, добавляемая в контекст. Значит, на него действуют те же законы, что и на любой промпт: расплывчатое игнорируется, длинное размывается, противоречивое исполняется случайным образом.

### 🎯 Зачем тебе

**1. Пожелания вместо правил.**
`«Пиши качественный, поддерживаемый код»` — не проверяемо, не исполнимо.
→ `«Все функции с type hints. Любой вызов БД — async. Тесты обязательны для новой бизнес-логики.»`

**2. Пересказ содержимого репозитория.**
Перечисление структуры каталогов устаревает через неделю и тратит контекст.
→ Оставьте то, что нельзя вывести из кода: договорённости, запреты, причины.

**3. Файл на 400 строк.**
Чем длиннее, тем меньше веса у каждого правила.
→ Держите 30–60 строк по существу; остальное — в документацию, куда агент сходит по ссылке.

**4. Запреты без причины.**
`«Не трогай gate.py»` — агент не понимает границ запрета.
→ `«Не менять логику TTL/деградации в gate.py без явного запроса: это самая чувствительная часть продукта.»`

**5. Правила, которые никто не соблюдает.**
Если в репозитории половина кода нарушает записанное правило, модель ориентируется на код, а не на файл.
→ Либо привести код в соответствие, либо убрать правило.

### 💻 Минимальный пример

```markdown
## Архитектура (не менять без явного запроса)
- Backend: FastAPI + asyncpg, схема PostgreSQL `baza`
- Все защищённые ручки — через `Depends(require_subscribed)`

## Code Style
- Python 3.12+, type hints везде, async для всех вызовов БД

## Definition of done
1. Работает локально через `docker compose up`
2. Не ломает гейт-флоу (проверить `/api/gate/check`)
```

Коротко, проверяемо, с указанием границ.

### ⚠️ Грабли

* **Файл не заменяет ревью.** Правила снижают частоту ошибок, но не гарантируют их отсутствие.
* **Копипаста чужого CLAUDE.md.** Чужие правила описывают чужой проект; толку от них ровно столько, сколько совпадений.
* **Обновляйте вместе с архитектурой.** Устаревший файл вреднее отсутствующего: он уверенно направляет не туда.
