### ❓ Что это

`CLAUDE.md` — не один файл, а слой правил. Claude Code подхватывает пользовательский файл (общий для всех ваших проектов), файл в корне репозитория (общий для команды) и файлы во вложенных каталогах (локальные для подсистемы). Все они складываются, а не заменяют друг друга.

### 🎯 Зачем тебе

* **Глобальный** — ваши личные привычки: язык ответов, стиль общения, любимые инструменты. Не уезжает в репозиторий.
* **Проектный** — правила, обязательные для всех, кто работает с кодом: команды сборки, архитектурные запреты, стиль. Лежит в git, ревьюится как код.
* **Вложенный** — специфика подсистемы: у фронтенда свои конвенции, у инфраструктурных скриптов свои.

Чем ближе файл к тому, над чем идёт работа, тем он специфичнее — и тем весомее при конфликте.

### 💻 Минимальный пример

```text
~/.claude/CLAUDE.md          → «отвечай по-русски, без вступлений»
repo/CLAUDE.md               → «Python 3.12, async для всех вызовов БД,
                                не менять схему без явного запроса»
repo/frontend/CLAUDE.md      → «React 18, без классовых компонентов,
                                стили только через токены из tokens.css»
```

Сгенерировать стартовый проектный файл можно командой `/init`.

### ⚠️ Грабли

* **Противоречия не подсвечиваются.** Если глобальный файл требует одного, а проектный другого, вы узнаете об этом по странному поведению агента, а не по ошибке.
* **Раздутый файл перестают читать — и люди, и модель.** Держите правила короткими и проверяемыми, «пиши хороший код» бесполезно.
* **Секретам здесь не место.** Проектный `CLAUDE.md` лежит в публичном или командном репозитории.
* **Можно отключить целиком.** Переменная `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` заставляет не загружать эти файлы вообще — полезно для отладки, опасно как постоянная настройка.
