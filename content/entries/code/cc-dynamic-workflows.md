### ❓ Что это

**Dynamic workflow** — JavaScript-скрипт, который оркестрирует много сабагентов сразу. Скрипт пишет
Claude под твою задачу, а рантайм выполняет его **в фоне**: сессия остаётся свободной, а в контекст
Claude попадает только итоговый ответ, а не транскрипты всех агентов.

Главное отличие — **кто держит план**:

| | Сабагенты | Agent teams | Workflows |
|---|---|---|---|
| Кто решает, что дальше | Claude, ход за ходом | лид-агент | **скрипт** |
| Где промежуточные результаты | контекст Claude | общий список задач | переменные скрипта |
| Масштаб | несколько задач за ход | горстка долгих пиров | десятки–сотни агентов |
| Прерывание | ход начинается заново | тиммейты продолжают | **возобновляется** в той же сессии |

### 🎯 Зачем тебе

Workflow нужен, когда задача больше, чем помещается в один контекст, или когда один и тот же шаг надо
прогнать по сотне файлов: аудит всех роутов на auth, миграция 500 компонентов JS→TS, исследование с
перекрёстной проверкой источников. Плюс к масштабу — **повторяемый паттерн качества**: независимые
агенты проверяют находки друг друга до того, как они попадут в отчёт.

### 💻 Как запустить

**Готовый workflow:**

```text
/deep-research Что изменилось в permission model Node.js между v20 и v22?
```

**Свой — ключевым словом в промпте** (или просто «используй workflow»):

```text
ultracode: проверь все обработчики в src/routes/ на отсутствие проверки auth и перепроверь каждую находку
```

**Режим на всю сессию** — Claude сам решает, где нужен workflow:

```text
/effort ultracode
```

Прогресс — в `/workflows`: фазы, агенты, их токены. Клавиши: `p` пауза, `x` стоп, `r` перезапуск
агента, `s` — **сохранить скрипт командой** в `.claude/workflows/` (общий для репо) или
`~/.claude/workflows/` (личный). Дальше он запускается как `/имя`.

Сохранённый скрипт выглядит так:

```javascript
export const meta = { name: 'audit-routes', description: 'Аудит роутов на auth' }

const found = await agent('Перечисли все .ts в src/routes/.', {
  schema: { type: 'object', required: ['files'], properties: { files: { type: 'array', items: { type: 'string' } } } },
})
const audits = await pipeline(found.files, f => agent(`Проверь ${f} на отсутствие auth.`, { label: f }))
return audits.filter(Boolean)
```

### ⚠️ Грабли

- **Это дорого.** Один прогон тратит заметно больше токенов, чем та же задача в диалоге, и съедает
  лимиты подписки. Сначала прогони на срезе — одна папка вместо репо. Предупреждение
  `Large workflow` загорается после 25 агентов или 1.5M прогнозных токенов, но ничего не
  останавливает.
- **`/effort ultracode` — на каждую задачу сессии.** Один запрос может превратиться в три workflow
  подряд. Выключай `/effort ultracode off`, когда вернулся к рутине.
- **Размер задаётся советом, а не лимитом:** `workflowSizeGuideline` — `small` (<5 агентов),
  `medium` (<10, дефолт), `large` (<50), `unrestricted`. Жёсткие лимиты рантайма: 16 агентов
  параллельно, 1000 агентов на прогон.
- **Нет ввода по ходу и нет `Date.now()`/`Math.random()`** — они бросают исключение, чтобы
  перезапуск повторял те же вызовы. Время передавай через `args`.
- **Упавший агент перезапускает всех, кто стартовал после него.** Совпавшие по промпту
  завершённые агенты возвращают сохранённый результат.
- **В `claude -p` и SDK подтверждения нет** — workflow проходит через обычные правила: разреши
  `Workflow` или `Workflow(имя)` в allow-rules.
- **Ключевое слово `ultracode` не срабатывает** из `-p`, расписаний, вебхуков и комментариев PR —
  только из промпта, который ты набрал сам.
