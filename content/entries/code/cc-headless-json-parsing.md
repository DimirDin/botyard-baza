### ❓ Что это

В headless-режиме агент запускается без интерактивного интерфейса и должен вернуть
результат чему-то автоматическому: шагу CI, скрипту, другому сервису. У CLI для этого есть
форматы вывода — обычный текст для человека и структурированный для машины.

Правило простое: **как только вывод читает программа, а не человек, переключайся
на структурированный формат.**

### 🎯 Зачем тебе

Грепать человекочитаемый вывод — классическая ловушка. Он не является контрактом:
формулировки меняются от версии к версии, появляются переносы строк, меняется оформление.
Пайплайн, построенный на `grep "Error"`, ломается тихо — он не падает, он начинает
пропускать ошибки.

| Что нужно узнать | Откуда брать |
|---|---|
| Успех или провал шага | Код возврата процесса |
| Итоговый текст модели | Поле результата в JSON |
| Расход токенов и стоимость | Поля usage в JSON |
| Ход выполнения в реальном времени | Потоковый формат, событие за событием |

### 💻 Минимальный пример

Скелет CI-шага, который не разваливается от смены формулировки:

```bash
set -euo pipefail

out="$(claude -p "$PROMPT" --output-format json)"

# результат — из поля, а не из текста
result="$(printf '%s' "$out" | jq -r '.result')"

# контроль расхода — оттуда же
cost="$(printf '%s' "$out" | jq -r '.total_cost_usd // 0')"

printf '%s\n' "$result" > review.md
echo "cost=$cost" >> "$GITHUB_OUTPUT"
```

Для длинных задач вместо одного JSON берётся потоковый формат: события приходят по мере
работы, и шаг CI не выглядит зависшим десять минут.

### ⚠️ Грабли

- **Забыть `set -o pipefail`.** `claude … | jq` вернёт код успеха от `jq`, даже если агент
  упал. Шаг CI станет зелёным на провале.
- **Не ограничить расход.** Агент в цикле CI без потолка стоимости — самый дорогой способ
  обнаружить баг в своём же скрипте.
- **Отдавать агенту секреты через аргументы командной строки.** Они видны в списке процессов
  и в логах CI. Только переменные окружения.
- **Логировать весь потоковый вывод в артефакты.** Это десятки мегабайт на запуск, и туда
  попадает содержимое файлов репозитория.
