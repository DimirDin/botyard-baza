### ❓ Что это

| Код | Что происходит |
|---|---|
| **0** | Успех. Stdout парсится как JSON (если начинается с `{`) либо как текст. Валидный JSON со схемой вступает в силу |
| **2** | Блокирующая ошибка. Блокирует на тех событиях, что поддерживают блокировку |
| Прочие | Обычно неблокирующая ошибка — действие продолжается |

Критичная деталь: **код 2 блокирует независимо от JSON**. Даже `permissionDecision: "allow"`
в выводе не отменит блокировку. Сообщение о блокировке берётся из причины в JSON-решении,
а если её нет — из stderr.

### 🎯 Зачем тебе

Универсальные поля JSON-вывода принимают все события:

```json
{
  "continue": false,
  "stopReason": "сообщение пользователю",
  "systemMessage": "предупреждение для Claude"
}
```

Решения складываются в `hookSpecificOutput`, и там обязательно указать `hookEventName`,
совпадающее с событием:

```json
{ "hookSpecificOutput": { "hookEventName": "PreToolUse", "permissionDecision": "deny" } }
```

### 💻 Минимальный пример

Где живут настройки хуков и что из этого шарится:

| Расположение | Область | Шарится |
|---|---|---|
| `~/.claude/settings.json` | все проекты | нет |
| `.claude/settings.json` | один проект | да, коммитится |
| `.claude/settings.local.json` | один проект | нет, в gitignore |
| Управляемая политика | организация | да, админом |
| `hooks/hooks.json` плагина | при включённом плагине | да |

### ⚠️ Грабли

- **Невалидный JSON — это неблокирующая ошибка, а не блокировка.** Действие продолжится,
  а ты будешь думать, что защита работает.
- **`WorktreeCreate` — исключение:** там **любой** ненулевой код проваливает создание.
- **Stdout виден Claude не везде.** Показывается на `UserPromptSubmit`,
  `UserPromptExpansion` и `SessionStart`; на остальных уходит в отладочный лог.
- **`suppressOutput` ничего не делает** — поле оставлено для совместимости.
