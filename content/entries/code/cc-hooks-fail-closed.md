### ❓ Что это

`onFailure` — поле хука, которое решает, что делать с действием, если **сам хук сломался**:

- `"continue"` — по умолчанию: действие выполняется, Claude Code показывает некритичную ошибку;
- `"block"` — действие останавливается так, как если бы хук вышел с кодом 2. На `PermissionRequest`
  поломка означает отказ.

Работает только у хуков типа `command` и `http`, с версии **2.1.295** (8 октября 2026).

### 🎯 Зачем тебе

Классическая дыра: ты написал PreToolUse-хук, который не даёт Claude выполнить опасную команду, а
потом переименовал папку, и скрипт перестал находиться. Без `onFailure` хук падает с
«не найден модуль», это считается некритичной ошибкой — и **команда выполняется**. Охранник есть
в конфиге, но ничего не охраняет, и ты об этом не знаешь.

`onFailure: "block"` превращает охранник из fail-open в **fail-closed**: если проверка не смогла
отработать, действие не проходит.

### 💻 Минимальный пример

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "node",
            "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/check-command.js"],
            "onFailure": "block"
          }
        ]
      }
    ]
  }
}
```

Если скрипта нет, вызов Bash блокируется с ошибкой
`hook error: [...]: failed; blocking because onFailure is "block"`, при таймауте — `timed out`.

#### Что считается поломкой

| Ситуация | Поломка? |
|---|---|
| Скрипт или бинарник не найден | да |
| Код выхода не 0 и не 2 (например, 1) | да — даже если хук напечатал `"allow"` |
| HTTP: нет соединения или ответ не 2xx | да |
| Хук упёрся в `timeout` | да |
| JSON не парсится или не проходит схему | да |
| Обычный текст в stdout у command-хука | нет |

### ⚠️ Грабли

- **Решение в JSON отдавай только с кодом 0.** Код 1 с `"permissionDecision": "allow"` — это поломка,
  и с `block` действие будет остановлено.
- **Код 2 всегда блокирует** на событиях, где блокировка возможна, и JSON его не перебьёт — даже
  `"allow"`. Причиной становится stderr.
- **Не действует на `Stop`, `SubagentStop`, `TaskCompleted`, `TeammateIdle`** (там код 2 значит
  «продолжай работать») и на фоновые хуки с `async`/`asyncRewake`.
- **Не ставь `block` на хуки, которые зависят от сети без нужды**: недоступный внешний сервис
  заблокирует работу целиком. Для логгеров и уведомлений оставь `continue`, для охранников — `block`.
- **Нужна версия 2.1.295+.** На старых версиях поле игнорируется, и охранник снова fail-open.
