### ❓ Что это

Хук — команда шелла, которую Claude Code запускает на событии: перед вызовом инструмента,
после него, при старте сессии. Соблазн думать о нём как о «шаге пайплайна, который
выполнится один раз». На практике — выполнится столько раз, сколько было событий,
и ты этим числом не управляешь.

### 🎯 Зачем тебе

Источники повторов, которые удивляют людей:

- **Параллельные вызовы инструментов.** Два `Edit` подряд — два `PostToolUse`, возможно,
  одновременно.
- **Прерванная сессия.** `PreToolUse` отработал, инструмент не выполнился: хук уже наследил.
- **Ретрай после ошибки.** Модель повторяет тот же вызов — хук идёт по второму кругу.
- **Несколько сессий в одном репозитории.** Worktree или просто второе окно.

Хук, который дописывает строку в файл, за такую сессию напишет её пять раз.

### 💻 Минимальный пример

Разница видна на самом частом сценарии — автоформатировании:

```bash
# ❌ не идемпотентно: добавляет запись каждый раз
echo "formatted $(date)" >> .format-log

# ❌ опасно: параллельные хуки дерутся за один временный файл
prettier --write src/ > /tmp/out.txt

# ✅ идемпотентно: результат один и тот же при любом числе запусков
prettier --write "$CLAUDE_FILE_PATH"
```

Форматирование само по себе идемпотентно — прогони его дважды, получишь тот же файл.
Именно поэтому оно хороший кандидат в хуки, а «отправить уведомление» — плохой.

### ⚠️ Грабли

- **Запускать в хуке git-коммиты.** Получишь мусорную историю из десятков автокоммитов,
  а при параллельных хуках — блокировку `index.lock`.
- **Считать, что хук успеет.** Долгий хук тормозит каждый шаг агента; событий за сессию
  сотни, и секунда превращается в минуты.
- **Молча падать.** Хук, который отваливается без внятного кода возврата, выглядит как
  «всё хорошо». Коды выхода — часть контракта, разбирай их осознанно.
- **Писать во временные файлы с фиксированным именем.** Два хука — гонка. Имя должно
  содержать идентификатор процесса.
