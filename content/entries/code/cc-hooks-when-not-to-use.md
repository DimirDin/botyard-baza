### ❓ Что это

Хуки — мощный механизм, и именно поэтому их легко переприменить. Каждый хук — это код, который выполняется на каждом соответствующем событии: он замедляет работу, ломается молча и требует поддержки. Прежде чем писать хук, стоит проверить, не решается ли задача дешевле.

### 🎯 Зачем тебе

| Задача | Чем лучше решить |
|---|---|
| «Всегда пиши тесты» | Правило в `CLAUDE.md` |
| «Перед коммитом прогнать линтер» | Обычный pre-commit hook в git |
| «Проверять стиль во всех PR» | CI, а не локальный хук |
| «Один и тот же многошаговый процесс» | Скилл или слэш-команда |
| «Никогда не читать .env» | **Хук** — нужна жёсткая блокировка |
| «Уведомить, когда агент закончил» | **Хук** — событие есть только здесь |
| «Не дать записать вне рабочего каталога» | **Хук** — нужна проверка в момент действия |

**Правило выбора:** хук нужен там, где важен *момент* (перехватить действие до выполнения) или *гарантия* (сработает всегда, независимо от решения модели). Всё остальное дешевле сделать другими средствами.

### 💻 Минимальный пример

```text
❌ Хук, который после каждой правки файла запускает полный прогон тестов.
   → Замедляет каждый шаг агента в разы; тесты гоняются на промежуточных,
     заведомо нерабочих состояниях.

✅ Правило в CLAUDE.md: «после завершения задачи прогони тесты»
   + хук-гейт только на коммит.
```

### ⚠️ Грабли

* **Хуки складываются.** Пять установленных наборов плагинов — это пять цепочек хуков на одно событие, и отладка становится нетривиальной.
* **Тихие падения.** Хук, который упал по ошибке в собственном коде, легко принять за странное поведение агента.
* **Стоимость на каждом шаге.** Медленный хук на частом событии — самый простой способ сделать работу с агентом невыносимой.
