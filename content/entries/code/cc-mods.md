### ❓ Что это

**Mod** — это плагин с JavaScript- или TypeScript-обработчиками событий, которые выполняются
**внутри процесса** Claude Code. Появились в версии **2.1.287** (1 октября 2026). Claude Code
вызывает обработчик на событие — вызов тула, отправку промпта, отрисовку части интерфейса, — и тот
может событие пропустить, переписать или обработать сам.

Чем это отличается от того, что уже было:

| | Mod | Settings-хук | Skill | MCP-сервер |
|---|---|---|---|---|
| Где работает | внутри Claude Code | внешний скрипт/HTTP | текст для Claude | внешний процесс |
| Рисует интерфейс | **да** | нет | нет | нет |
| Пишешь на | JS/TS | любой скрипт | Markdown | любой язык |
| Бери, когда | нужна панель, команда, переписать событие | заблокировать/разрешить/залогировать | одни и те же инструкции | доступ к внешней системе |

### 🎯 Зачем тебе

Mods закрывают то, что раньше не делалось вообще:

- **Своя панель или полоса над промптом** — например, график заполнения контекста после каждого
  запроса.
- **Перерисовать интерфейс Claude Code** — строку вызова тула, спиннер, диалог вопросов.
- **Встать в вызов тула**: придержать `rm -rf` и показать, что он заденет, ответить без запуска тула,
  отправить один запрос в другую модель.
- **`/команда`, которая сразу выполняет твой код** — без хода модели, даже пока Claude работает.

Часть функций самого Claude Code уже сделана модами: `/diff`, загрузка `AGENTS.md`.

### 💻 Минимальный пример

Мод — обычный плагин из трёх файлов:

```text
first-mod/
├── .claude-plugin/plugin.json
└── hooks/
    ├── hooks.json      # указывает на register.js
    └── register.js     # сам код
```

`register.js` считает вызовы тулов и дописывает счётчик к спиннеру:

```javascript
let calls = 0

export function register(on) {
  on('tool.call', async ($, e, next) => {
    calls += 1
    $.ui.invalidate('ui.render')   // перерисовать, чтобы счётчик обновился
    return next(e)                 // тул выполняется как обычно
  })

  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    return next({ ...e, props: { ...e.props, suffix: ' · tool calls: ' + calls + '…' } })
  })
}
```

Писать руками не обязательно: опиши мод в сессии, и Claude напишет его встроенным скиллом
`plugin-authoring`. Установка — как у любого плагина:
`/plugin install имя@маркетплейс`, после установки из шелла — `/reload-plugins`.

Готовые примеры от Anthropic — в `anthropics/claude-code-playground`, папка `claude-code/mods`:
`token-weather` (прогноз контекста над промптом), `blast-radius` (придерживает опасные команды
с кнопками «выполнить/отмена»), `replay-theater` (`/replay` по правкам последнего хода).

### ⚠️ Грабли

- **Мод — это код с твоими правами, без песочницы.** Он читает и пишет любые файлы, видит переменные
  окружения с ключами, каждый промпт и вызов тула, может сам одобрить вызов, который запретил бы
  твой `ask`-rule или PreToolUse-хук. Sandbox Claude Code изолирует Bash, но не процессы мода.
  Ставь моды только от авторов и маркетплейсов, которым доверяешь.
- **Проверяй до установки:** `claude plugin validate ./some-mod` выводит строки `hooks:` и `calls:` —
  какие события мод слушает и что просит сделать, без запуска кода.
- **Отрисовка работает не везде.** Хуки мода выполняются и в `claude -p`, и в облачной сессии, но
  панели видны только в терминале, Desktop и VS Code. Плагины не работают в WSL-сессиях Desktop.
- **Выключить все свои моды разом** — `--safe-mode` на одну сессию или `"disableAllHooks": true`
  в `~/.claude/settings.json` (выключит и settings-хуки). Встроенные моды эти флаги не трогают.
- **Окно запроса разрешения мод изменить не может** — это сознательная граница безопасности.
