### ❓ Что это

Делегирование задач в Claude Code — это архитектурный паттерн, при котором главный агент (Orchestrator) выгружает исследовательские, тестовые или узкоспециализированные подзадачи независимым ведомым суб-агентам (`Subagent`). Каждый суб-агент выполняется со своим изолированным контекстным окном и отдельным системным промптом, после чего возвращает лидеру только результирующий отчёт.

В сложных репозиториях попытка решить всю задачу в рамках единого сеанса приводит к быстрой замусоренности контекста (context rot) и падению качества рефакторинга. Использование суб-агентов позволяет сохранять контекст лидера чистым.

---

### 🎯 Для чего

1. **Параллельное исследование кода**: Запуск нескольких исследователей для анализа разрозненных частей монорепозитория без замусоривания главного окна.
2. **Безопасная изоляция эксперимента**: Проведение потенциально деструктивных изменений в отдельной Git-ветке воркспейса суб-агента (`Workspace: branch`).
3. **Экономия токенов**: Суб-агенты могут работать на более быстрых и лёгких моделях (`flash` или `flash_lite`), экономя бюджет основного сеанса.
4. **Специализация ролей**: Кастомные промпты ролей (например, `Database Debugger`, `Security Auditor`) для более точного выполнения специализированных фаз.

---

### 💻 Как настроить и вызывать

Инструмент `invoke_subagent` принимает список объектов суб-агентов с их ролями, промптами и режимом модели:

```json
{
  "Subagents": [
    {
      "TypeName": "research",
      "Role": "Codebase Researcher",
      "Model": "flash",
      "Prompt": "Найди все места вызовов устаревшего API v1 в модулях платежей и составь список файлов с номерами строк."
    },
    {
      "TypeName": "self",
      "Role": "Unit Test Engineer",
      "Model": "pro",
      "Workspace": "branch",
      "Prompt": "Напиши юнит-тесты для нового модуля авторизации в isolated branch и убедись, что npm test проходит."
    }
  ]
}
```

#### Режимы выполнения изолированных воркспейсов:
- `inherit` — суб-агент работает в основном каталоге проекта вместе с главным агентом.
- `branch` — создает изолированную Git-ветку для изменений суб-агента.
- `share` — создаёт git-worktree с изолированным состоянием рабочей директории.

### ⚠️ Грабли

- **Перегрузка лидера лишними сообщениями**: Не опрашивайте статус суб-агентов в бесконечном цикле (polling). Система автоматически уведомит главного агента при завершении или сообщении от суб-агента.
- **Гонка прав на файлы**: Если два суб-агента работают в режиме `Workspace: inherit` и одновременно редактируют один и тот же файл, возможен конфликт перезаписи. Используйте `Workspace: branch` для редактирующих агентов.
- **Потеря релевантного контекста**: Всегда передавайте суб-агенту точные пути к файлам и сигнатуры функций в промпте — он не видит предыдущую историю сообщений главного сеанса.
