### ❓ Что это

Профилирование и мониторинг работы **Claude Code** — это процесс контроля за тем, сколько ресурсов (памяти, времени процессора) и, самое главное, токенов контекстного окна расходует интерактивная сессия CLI-агента при выполнении задач в репозитории.

### 🎯 Зачем тебе

Длительные интерактивные сессии с агентом склонны накапливать огромную историю диалога. Это приводит к двум проблемам:
1. **Рост стоимости**: Каждый новый запрос отправляет всю накопленную историю, что увеличивает плату за входящие токены.
2. **Замедление ответов**: Чем больше контекст, тем выше задержка (latency) до начала генерации ответа модели.
Контроль лимитов позволяет вовремя сжимать сессию (`/compact`) или начинать новый чистый диалог (`/clear`).

### 💻 Как это сделать

Чтобы увидеть текущую статистику использования токенов и лимиты в вашей активной сессии Claude Code, используйте специальный флаг при запуске или команды внутри консоли:

```bash
# Запуск Claude Code с выводом статистики по потреблению токенов после каждого шага
claude --verbose
```

Внутри терминала Claude Code:
* `/compact` — принудительно сжимает историю сообщений, удаляя промежуточные детали работы инструментов, но сохраняя выводы.
* `/clear` — сбрасывает контекст текущей беседы целиком, начиная чистый лист без потери изменений в кодовой базе.

### ⚠️ Грабли

* **Раздувание контекста при поиске по файлам**: Если вы попросите агента найти что-то без указания конкретных папок, он может просканировать сотни файлов, прочитав их содержимое в контекст, что мгновенно исчерпает доступный лимит токенов. Всегда сужайте область поиска для агента.
* **Следите за логами сборки**: Если запущенный тест или сборка проекта падает и генерирует мегабайты логов в stdout, Claude Code прочитает все эти логи целиком, что приведет к перерасходу токенов. Настраивайте тихий вывод тестов (`pytest -q` и т.п.).
