### ❓ Что это

Для крупных проектов инструкции раскладываются по файлам в `.claude/rules/`. Все `.md`
находятся рекурсивно, так что можно раскладывать по подпапкам:

```text
your-project/
├── .claude/
│   ├── CLAUDE.md
│   └── rules/
│       ├── code-style.md
│       ├── testing.md
│       └── security.md
```

Главная возможность — **привязка к путям**. Правило с полем `paths` во фронтматтере
попадает в контекст, только когда Claude работает с подходящими файлами:

```markdown
---
paths:
  - "src/api/**/*.ts"
---

# API Development Rules
- All API endpoints must include input validation
```

### 🎯 Зачем тебе

Целевой размер CLAUDE.md — **менее 200 строк**: файлы длиннее едят контекст и снижают
следование инструкциям. Правила с путями решают ровно эту проблему: инструкции по API
не занимают место, пока ты правишь фронтенд.

Правила **без** поля `paths` грузятся на старте с тем же приоритетом, что `.claude/CLAUDE.md`.

### 💻 Минимальный пример

Глобы в `paths`:

| Шаблон | Что ловит |
|---|---|
| `**/*.ts` | Все TypeScript-файлы в любой директории |
| `src/**/*` | Всё под `src/` |
| `*.md` | Markdown в корне проекта |
| `src/**/*.{ts,tsx}` | Расширения через фигурные скобки |

Правила можно шарить между проектами симлинками — они резолвятся и грузятся нормально,
циклические обнаруживаются и обрабатываются корректно:

```bash
ln -s ~/shared-claude-rules .claude/rules/shared
```

### ⚠️ Грабли

- **Path-правила срабатывают на чтение подходящего файла, а не на любой вызов инструмента.**
- **Фигурные скобки размножают шаблоны.** У списка `paths` общий бюджет в 1000 развёрнутых
  шаблонов и 4 МиБ; шаблон, выходящий за бюджет, используется неразвёрнутым и не матчит ничего.
- **`[` — начало скобочного выражения.** `photos [2024/**` невалиден и не матчит ничего;
  для литеральной скобки экранируй: `photos \[2024/**`.
- **Для задачных инструкций лучше скиллы.** Правила грузятся каждую сессию или при открытии
  файлов; скилл подтягивается только когда нужен.
