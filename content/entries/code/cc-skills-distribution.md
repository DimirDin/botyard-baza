### ❓ Что это

Написанный скилл нужно как-то донести до остальных. Сложились три способа: положить в репозиторий проекта, оформить плагин и раздавать через маркетплейс, либо использовать кроссагентный установщик формата Agent Skills.

### 🎯 Зачем тебе

**1. В репозиторий проекта.**
Скиллы лежат рядом с кодом, приезжают вместе с `git pull`, ревьюются в PR. Проще всего и лучше всего для правил, специфичных для одного проекта.

**2. Плагин + маркетплейс.**
```bash
/plugin marketplace add <owner>/<repo>
/plugin install <plugin>@<marketplace>
```
Штатный механизм Claude Code: версионирование, обновления, установка по частям. Подходит, когда набор используется в нескольких проектах или отдаётся наружу.

**3. Универсальный установщик.**
```bash
npx skills add <owner>/<repo> --all
npx skills add <owner>/<repo> --skill <имя>
```
Формат Agent Skills переносим между агентами — тот же набор поедет и в Codex, и в Cursor. Цена — отказ от специфичных возможностей Claude Code.

### 💻 Минимальный пример

Выбор по ситуации:

```text
Скилл про конвенции этого репозитория     → в репозиторий
Набор для всей команды на всех проектах   → плагин + маркетплейс
Публичный набор для разных агентов        → формат Agent Skills
```

### ⚠️ Грабли

* **Установка чужого плагина = запуск чужого кода.** В плагинах бывают хуки, выполняющиеся автоматически с вашими правами. Смотрите содержимое перед установкой.
* **Обновления не приезжают сами.** Скопированный в репозиторий скилл не обновится, когда автор исправит ошибку.
* **Версии Claude Code.** Многие маркетплейсы требуют свежую версию CLI и падают на старой без внятного сообщения.
* **Конфликт имён.** Два набора с одинаково названными командами дают непредсказуемый результат.
