### ❓ Что это

**Прогрессивное раскрытие контекста** — принцип, на котором держатся скиллы: в контекст постоянно загружено только короткое описание («что это и когда применять»), а подробная инструкция подтягивается лишь тогда, когда скилл действительно понадобился. Поэтому можно держать десятки скиллов, не платя за них контекстом на каждом запросе.

### 🎯 Зачем тебе

* **Описание — это интерфейс.** По нему принимается решение, брать скилл или нет. Плохое описание = скилл не вызывается никогда либо вызывается не к месту.
* **Тело может быть большим.** Раз оно грузится по требованию, туда не жалко положить подробный процесс, примеры и краевые случаи.
* **Масштабируется.** Двадцать узких скиллов работают лучше, чем один универсальный на 500 строк.

### 💻 Минимальный пример

```markdown
---
name: release-notes
description: Use when preparing release notes from merged PRs — collects
  changes since the last tag, groups by semver impact, flags breaking changes.
---

## Процесс
1. Найти последний тег: `git describe --tags --abbrev=0`
2. Собрать merged PR с этого момента
3. Сгруппировать: breaking / features / fixes / chore
4. Отдельным блоком — миграции и ручные шаги
...
```

Обратите внимание на `description`: там указано **когда** применять, а не только что это такое. Это главное, по чему принимается решение о вызове.

### ⚠️ Грабли

* **Описание вида «помогает с релизами» бесполезно.** Нет триггера — нет вызова.
* **Скилл, который делает всё, не вызывается ни на что.** Разбивайте по задачам.
* **Тело всё-таки попадает в контекст при вызове.** Скилл на тысячу строк, вызванный в середине длинной сессии, вытеснит то, над чем вы работали.
* **Проверяйте, что скилл реально подхватился.** Если результат не отличается от обычного ответа — вероятно, он и не вызывался.
