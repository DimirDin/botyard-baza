### ❓ Что это

Скилл подключается не по имени файла и не по папке, а по полю `description` во фронтматтере.
Модель видит **только** `name` и `description` всех установленных скиллов — тело `SKILL.md`
подгружается уже после того, как решение вызвать скилл принято. Отсюда главный симптом:
скилл написан отлично, но не срабатывает никогда.

### 🎯 Зачем тебе

Отладка идёт не в теле скилла, а в одной строке описания. Типичный неработающий вариант:

```yaml
description: Helper for reports
```

Под это описание модель не подведёт ни один реальный запрос. Рабочее описание отвечает
на два вопроса — **что делает** и **когда применять**, причём словами пользователя,
а не внутренней терминологией:

```yaml
description: >
  Собирает недельный отчёт по выручке из выгрузки CRM.
  Использовать, когда просят «отчёт за неделю», «сводку по продажам»,
  «сколько сделали за период».
```

### 💻 Минимальный пример

Цикл проверки — три шага, каждый честно даёт ответ «да/нет»:

```
1. Скилл вообще установлен?      → /skills или вывод при старте сессии
2. Модель его видит как подходящий? → «какие скиллы подойдут для задачи X?»
3. Срабатывает на живом запросе?  → сформулируй задачу так, как сформулировал бы пользователь
```

Шаг 2 — самый полезный и его почти никто не делает. Если на прямой вопрос модель скилл
не называет, то в реальном диалоге он не вызовется тем более: там конкуренция с остальным
контекстом. Правишь `description`, перезапускаешь сессию, спрашиваешь снова.

### ⚠️ Грабли

- **Тестировать фразой «используй скилл X».** Это проверяет, что файл читается, и ничего
  не говорит о том, вызовется ли он сам. Тестируй формулировкой задачи, а не команды.
- **Забывать перезапустить сессию.** Описания скиллов собираются в начале сессии; правка
  `description` на лету ни на что не влияет.
- **Два скилла с пересекающимися описаниями.** Модель выберет один и будет выбирать его
  стабильно — второй окажется мёртвым кодом. Границы применимости разводи явно.
- **Держать в `description` внутренний жаргон компании.** Пользователь напишет «сводка»,
  а в описании стоит «агрегированный P&L-срез» — совпадения не будет.
