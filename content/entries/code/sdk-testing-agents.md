### ❓ Что это

Обычный юнит-тест устроен как «вход → ожидаемый выход». С агентом это не работает:
на один и тот же вход он дважды вернёт разный текст, и оба раза правильно.

Поэтому тестируют не формулировку, а **наблюдаемое поведение** — след из вызовов
инструментов, который агент оставил по дороге. Он структурирован и детерминирован гораздо
сильнее, чем текст.

### 🎯 Зачем тебе

Три слоя, и путать их дорого:

| Слой | Чем проверяется | Скорость |
|---|---|---|
| Инструменты | Обычные юнит-тесты, без модели вообще | Миллисекунды |
| Траектория | Фейковые инструменты, проверка вызовов | Секунды |
| Качество ответа | Эвал на датасете, судья или ручная разметка | Минуты и деньги |

Львиная доля багов живёт на первом слое — в самих инструментах — и ловится без единого
обращения к модели. Гонять для этого полноценный эвал значит платить деньги за обнаружение
опечатки в SQL-запросе.

### 💻 Минимальный пример

Средний слой — самый недооценённый. Инструменты подменяются заглушками, которые пишут
журнал вызовов:

```python
calls = []

async def fake_search(query: str) -> str:
    calls.append(("search", query))
    return "результатов не найдено"

async def fake_write(path: str, text: str) -> str:
    calls.append(("write", path))
    return "ok"

await run_agent("найди упоминания X и сохрани в отчёт", tools=[fake_search, fake_write])

# утверждение про поведение, а не про текст
assert calls[0][0] == "search"
assert not any(c[0] == "write" for c in calls), "не должен писать отчёт по пустой выдаче"
```

Последняя строка — типичный регресс: агент послушно создаёт пустой отчёт вместо того,
чтобы сказать, что данных нет.

### ⚠️ Грабли

- **Ассертить точный текст ответа.** Тест будет краснеть на каждой смене модели, и его
  отключат — вместе с настоящими регрессами.
- **Ходить в реальные API из тестов.** Медленно, платно, и агент может что-то изменить
  в настоящей системе. Заглушки не опция, а требование.
- **Ловить только счастливый путь.** Самое ценное — сценарии «инструмент вернул ошибку»
  и «данных нет»: именно там агент начинает выдумывать.
- **Считать эвал заменой тестам.** Эвал меряет качество на распределении задач,
  а не корректность конкретного вызова. Нужны оба.
