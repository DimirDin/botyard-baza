### ❓ Что это

Между «красивым артефактом» и «компонентом в проекте» лежит слой работы, который модель по умолчанию не делает: состояния, краевые случаи, интеграция с вашей системой. Если попросить их явно, перенос перестаёт быть переписыванием с нуля.

### 🎯 Зачем тебе

Чек-лист, который стоит прогнать до переноса:

```text
[ ] Состояния: загрузка, пусто, ошибка, отказ в доступе, частичные данные
[ ] Краевые данные: длинное имя, ноль элементов, 999+ элементов,
    отсутствующая картинка, очень длинный текст без пробелов
[ ] Токены проекта вместо жёстко прописанных цветов и размеров
[ ] Доступность: семантические теги, порядок фокуса, alt, aria там,
    где семантики не хватает
[ ] Поведение: что происходит при повторном нажатии, при медленной сети
[ ] Тёмная и светлая тема
[ ] Компонент не завязан на глобальные стили страницы-артефакта
```

### 💻 Минимальный пример

```text
Перенеси этот макет в React-компонент нашего проекта.

Ограничения:
- только токены из tokens.css, никаких хардкодных цветов
- состояния: loading (скелетон), empty, error — все три обязательны
- никаких внешних зависимостей, кроме уже используемых в проекте
- пропсы типизировать
- компонент должен корректно выглядеть при name длиной 60 символов
  и при отсутствующем avatar_url

Покажи отдельно: что в макете было решено «на глаз» и требует
моего решения перед мержем.
```

Последний абзац экономит больше всего времени — он вытаскивает неявные допущения.

### ⚠️ Грабли

* **Артефакт самодостаточен, компонент — нет.** Стили, которые в артефакте лежали глобально, в проекте начнут течь наружу.
* **Внешние зависимости.** Сгенерированный макет любит тянуть библиотеку ради одной иконки.
* **Пиксельная точность — ложная цель.** Соответствие дизайн-системе важнее совпадения с макетом до пикселя.
* **Доступность добавляют в конце и потому не добавляют.** Просите сразу.
