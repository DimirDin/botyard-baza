### ❓ Что это

**Токены** — именованные переменные дизайна: цвета, шаги шкалы отступов, размеры шрифта, радиусы, тени. Модель хорошо генерирует их именно как *систему*, если попросить систему, а не список значений.

### 🎯 Зачем тебе

* **Связность.** Сгенерированная шкала из восьми шагов согласована между собой; восемь отдельно придуманных значений — нет.
* **Переносимость.** Один набор токенов раскладывается и в CSS-переменные, и в конфиг фреймворка, и в переменные макета.
* **Правки становятся дешёвыми.** Поменять акцентный цвет во всём продукте — это одна строка.

### 💻 Минимальный пример

```text
Собери набор дизайн-токенов для тёмной редакторской темы.

База: фон #16130F, акцент терракота #E08256.

Нужно:
- 4 уровня поверхностей (фон → карточка → приподнятая карточка → граница)
- 3 уровня текста (основной, вторичный, приглушённый) с проверкой
  контраста по WCAG AA на каждой поверхности
- шкала отступов из 6 шагов, база 4px
- шкала размеров шрифта из 6 шагов
- 3 радиуса скругления
Формат: CSS custom properties, с комментарием назначения у каждого токена.
Отдельно укажи пары, которые НЕ проходят по контрасту.
```

Последняя строка важна: без неё контраст «проверяется» на словах.

### ⚠️ Грабли

* **Контраст надо проверять инструментом.** Модель может ошибиться в расчёте — прогоняйте итог через любой чекер WCAG.
* **Красивая палитра ≠ рабочая палитра.** Проверяйте на реальном интерфейсе с плотным текстом и мелкими элементами, а не на демо-карточке.
* **Слишком много токенов.** Двадцать оттенков серого никто не будет различать; система из 4–6 уровней используется, из двадцати — нет.
* **Именование решает.** `--color-surface-raised` переживёт редизайн, `--color-gray-3` — нет.
