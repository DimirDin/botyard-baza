### ❓ Что это

`effort` управляет тем, сколько рассуждения модель прикладывает к ответу. Более низкие
уровни тратят меньше токенов за ход и снижают стоимость. Поддерживают его не все модели.

| Уровень | Поведение | Для чего |
|---|---|---|
| `low` | Минимальное рассуждение, быстрые ответы | Поиск файлов, листинг директорий |
| `medium` | Сбалансированно | Рутинные правки, обычные задачи |
| `high` | Тщательный анализ | Рефакторинги, отладка |
| `xhigh` | Расширенная глубина | Кодинг и агентные задачи; рекомендован на Fable 5, Opus 4.7+ и Sonnet 5 |
| `max` | Максимальная глубина | Многошаговые задачи, требующие глубокого анализа |

### 🎯 Зачем тебе

Это самая прямая ручка «цена ↔ качество» из всех доступных. Агенту, который только читает
файлы и делает один grep, `high` не даст ничего, кроме счёта: документация прямо советует
низкий effort для простых, узко очерченных задач.

Если не задать `effort` вовсе — оба SDK оставляют параметр неустановленным и полагаются на
поведение модели по умолчанию.

### 💻 Минимальный пример

Уровень задаётся либо на всю сессию, либо на конкретного сабагента — поле `effort` в
`AgentDefinition` переопределяет сессионный:

```python
options = ClaudeAgentOptions(
    allowed_tools=["Read", "Glob"],
    effort="low",        # агент только читает — глубокое рассуждение не нужно
)
```

Разумная схема для многоагентной работы: `low` у собирающих информацию сабагентов,
`high`/`xhigh` — у того, кто принимает решение по собранному.

### ⚠️ Грабли

- **Не путать с extended thinking.** Это два независимых механизма (см. отдельную статью):
  можно поставить `effort: "low"` с включённым extended thinking и наоборот.
- **Не все модели поддерживают параметр.** Сверяйся со страницей Effort, а не с ожиданием.
- **`max` не «всегда лучше».** Он меняет и латентность, и стоимость — на рутине это чистый
  проигрыш по обоим измерениям без выигрыша по качеству.
