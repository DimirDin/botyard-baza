### ❓ Что это

SDK и `ant` CLI ищут креденшелы в фиксированном порядке — **побеждает первый найденный**:

1. `ANTHROPIC_API_KEY`
2. `ANTHROPIC_AUTH_TOKEN`
3. профиль OAuth — выбранный через `ANTHROPIC_PROFILE` или активный после `ant auth login`
4. переменные Workload Identity Federation
5. профиль по умолчанию на диске

Отсюда главный вывод, который экономит часы: **незаданный `ANTHROPIC_API_KEY` не означает,
что креденшелов нет.** Голый `Anthropic()` прекрасно работает после `ant auth login`
безо всяких переменных окружения.

### 🎯 Зачем тебе

Две типовые ситуации. Первая: код падает с 401, хотя «ключ точно есть» — на самом деле
подхватился другой источник. Вторая: коллеге говорят «экспортируй ключ», хотя достаточно
было залогиниться.

### 💻 Минимальный пример

Первое, что стоит сделать при непонятной авторизации:

```bash
ant auth status
```

Команда показывает, **какой источник и какой профиль** сейчас активен.

```python
from anthropic import Anthropic
client = Anthropic()      # подхватит активный профиль, если переменных нет
```

### ⚠️ Грабли

- **Экспортированный API-ключ затеняет профиль.** Даже если ты залогинен, переменная
  выигрывает — она первая в списке. Это самая частая причина «почему используется не тот аккаунт».
- **Пустая переменная — это тоже заданная переменная.** `ANTHROPIC_API_KEY=""` перебивает
  WIF и профиль, и всё ломается с невнятной ошибкой.
- **`ANTHROPIC_PROFILE` с несуществующим именем — ошибка, а не откат** к профилю по умолчанию.
- Профили лежат в `~/.config/anthropic/` и читаются SDK автоматически — отдельной настройки
  в коде не нужно.
