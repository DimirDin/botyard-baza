### ❓ Что это

Два разных объекта, которые новички склеивают в один.

**Agent** — персистентный версионируемый конфиг: модель, системный промпт, набор инструментов,
окружение. Создаётся редко, живёт долго, имеет версии.

**Session** — один прогон. Ссылается на агента, прибивается (пинится) к его версии на момент
старта, стримит события, принимает сообщения и результаты инструментов.

Правило, из которого растёт всё остальное: **`model`, `system` и `tools` — поля агента, а не сессии.**

### 🎯 Зачем тебе

Разделение даёт то, чего нет в обычном цикле на Messages API: обновление конфигурации не ломает
уже запущенное. Ты выкатил новую версию системного промпта — сессии, стартовавшие раньше,
доигрывают на старой версии, новые подхватывают новую. Это единственный способ безопасно
править промпт агента, который может работать часами.

### 💻 Минимальный пример

Статусы сессии, на которые завязана вся клиентская логика:

| Статус | Что значит | Тарифицируется |
|---|---|---|
| `running` | агент работает | да |
| `idle` | ждёт твоего сообщения или подтверждения тула | нет |
| `rescheduling` | переезжает | нет |
| `terminated` | закончена | нет |

```python
session = client.beta.sessions.create(agent_id=AGENT_ID)

with client.beta.sessions.stream(session.id) as stream:
    for event in stream:
        ...  # обрабатываем события по мере поступления
```

Выход из цикла делай по статусу (`idle` / `terminated`), а не по «событий больше не пришло».

### ⚠️ Грабли

- **Гонка после idle** — статус может обновиться позже последнего события стрима. Читай стрим
  первым, статус вторым, иначе поймаешь ложное «всё кончилось».
- **Обрыв стрима** — переподключение должно быть без потерь; для этого есть гейт
  `processed_at` (queued/processed), чтобы не обработать одно событие дважды.
- **Пиннинг работает в обе стороны** — если ты ждал, что старая сессия подхватит новый промпт,
  она этого не сделает. Это фича, но она удивляет.
- **`tool_confirmation` — это раунд-трип.** Сессия уходит в `idle` и ждёт. Если клиент не ответил,
  она будет ждать бесконечно, не тратя runtime, но и не двигаясь.
