### ❓ Что это

**Prompt Caching** (кэширование промптов) — это механизм в API Anthropic, позволяющий кэшировать статические части ваших запросов (системные инструкции, описания инструментов, большие файлы контекста или историю диалога). При повторных запросах Claude не обрабатывает эти токены заново, а читает их из быстрого кэша, что ускоряет время генерации первого токена (TTFT) и снижает стоимость входящих токенов до 90%.

### 🎯 Зачем тебе

1. **Экономия бюджета**: Стоимость чтения из кэша (cached input tokens) составляет лишь 10% от стоимости стандартных входящих токенов. Например, для Claude 3.5 Sonnet: $3.00 за млн токенов без кэша и всего $0.30 с кэшем.
2. **Скорость работы (Latency)**: Кэшированные запросы обрабатываются значительно быстрее (до 2-4 раз), особенно при работе с большими объемами данных (книги, кодовые базы, длинные логи).
3. **Сохранение контекста**: Вы можете держать в контексте огромную документацию или весь проект без оглядки на лавинообразный рост затрат при каждом новом сообщении.

### 💻 Как настроить кэширование в коде

Для включения кэширования необходимо добавить параметр `"cache_control": {"type": "ephemeral"}` к блокам сообщений или системных инструкций, которые вы хотите закэшировать.

Пример на Python с использованием официального SDK:

```python
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": "Ты эксперт по базам данных. Твоя инструкция...",
            "cache_control": {"type": "ephemeral"}  # Кэшируем системный промпт
        }
    ],
    messages=[
        {
            "role": "user",
            "content": "Какой индекс создать для оптимизации запросов?"
        }
    ]
)
```

### ⚠️ Грабли и правила

* **Минимальный размер кэша**: Кэширование работает только для запросов с объемом контекста выше определенного порога. Для моделей **Claude 3.5 Sonnet** и **Claude 3 Opus** минимальный порог составляет **1024 токена**. Для **Claude 3.5 Haiku** порог равен **2048 токенам**. Запросы меньшего размера кэшироваться не будут.
* **Время жизни кэша (TTL)**: Кэш является эфемерным и живет **5 минут** после последнего обращения. Каждое попадание в кэш (cache hit) обновляет этот 5-минутный таймер.
* **Порядок имеет значение**: Кэш строится последовательно сверху вниз. Вы не можете закэшировать блок, если перед ним идет некэшированный блок. Всегда располагайте самую статическую информацию (системный промпт, инструменты, базу знаний) в самом начале запроса и помечайте её для кэширования, а динамический ввод пользователя — в самом конце.
* **Лимиты точек кэширования**: В одном запросе можно установить максимум **4 контрольные точки кэширования** (cache breakpoints).
