### ❓ Что это
MCP — стандарт, по которому Claude получает доступ к внешним данным и действиям. Готовых серверов много, но рано или поздно упираешься в своё: внутренняя база, корпоративная вики, самописный сервис. Тогда пишешь сервер сам — это существенно меньше работы, чем кажется.

Сервер объявляет набор инструментов: у каждого есть имя, описание и схема входных параметров. Claude читает описания и сам решает, какой инструмент вызвать под задачу. Твой код получает вызов, делает работу и возвращает результат.

### 🎯 Зачем тебе
Пока данных нет в контексте, агент про них не знает и начинает угадывать. Один маленький сервер, отдающий актуальную схему твоей БД или список открытых инцидентов, убирает целый класс ошибок «модель придумала таблицу, которой нет».

Второй мотив — действия, а не только чтение. Сервер может не просто отдавать данные, но и создавать задачи, дёргать деплой, писать в очередь.

### 💻 Как это выглядит на практике
Минимальный сервер описывает инструмент и обработчик:

```python
@server.tool()
async def get_order(order_id: str) -> str:
    """Возвращает статус заказа по его идентификатору."""
    row = await db.fetchrow("SELECT status, updated_at FROM orders WHERE id = $1", order_id)
    return f"Статус: {row['status']}, обновлён {row['updated_at']}"
```

Ключевая деталь, которую все недооценивают: **описание инструмента — это промпт**. По нему модель решает, звать инструмент или нет. Расплывчатое «работа с заказами» приведёт к тому, что его будут звать невпопад или не звать вовсе.

Подключение к Claude Code — командой `claude mcp add` либо записью в `.mcp.json` проекта.

### ⚠️ Частая ошибка новичка
Отдавать из инструмента сырой дамп: весь ответ API целиком, всю таблицу, весь лог. Это тысячи токенов контекста за один вызов, и большая часть из них бесполезна. Возвращай ровно то, что нужно для решения, в компактном виде.

Вторая ошибка — забыть, что сервер работает с правами того, кто его запустил. Инструмент, умеющий выполнить произвольный SQL, — это дыра, а не удобство.
